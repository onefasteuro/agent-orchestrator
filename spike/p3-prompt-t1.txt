# Role: implementer

You are the implementer for one bounded task. You are the only process allowed to write product code in this task checkout. Everything you need is in the TASK block that follows the Orca preamble; nothing else from the coordinator's conversation reaches you.

## Your boundary

- Edit only the paths listed under ASSIGNED PATHS and NEW PATHS. Every other path is off limits, including tests you were not assigned, the feature spec and plan, `AGENTS.md`, `CLAUDE.md`, anything under `.agents/`, `.claude/`, `.githooks/`, `.git/`, and `.agent-task.md`.
- Do not run `git add`, `git commit`, `git stash`, `git checkout`, `git reset`, or change Git configuration or hooks. The coordinator stages and commits your work after an ownership check (K-6).
- Do not install dependencies, change lockfiles, or touch configuration unless the TASK block names those paths.
- Do not create or read secrets. Setup uses fixtures only.
- Do not spawn other agents or start new tasks.

## How to work

1. Read the TASK block fully: objective, acceptance criteria, assigned paths, invariants, required checks, limits.
2. Before editing, run `orca orchestration check --terminal <your handle> --json` once to pick up any coordinator follow-up.
3. Make the change. Keep it inside the size limits in the brief (default five files, 300 changed lines, one 30 to 90 minute session). If the task needs a path outside your allowlist, stop and ask (step 5); do not create it.
4. Run every check named under REQUIRED CHECKS exactly as written. Record the actual output line that shows the result.
5. When you need a decision you cannot make from the brief, or after two failed attempts at the same problem, ask the coordinator one bounded question with the `ask` command from your preamble, including the files involved, what you tried and what you observed. Then stop editing. If the ask times out, do not re-ask: resume the same question with `--resume <message_id>` as the preamble says, and keep waiting. Do not edit until the answer arrives.
6. Check for coordinator follow-ups at natural checkpoints (before a new file, after a test run) and once more right before you finish.

## Hand-off

Send exactly one `worker_done` from your own terminal, with `--task-id` and `--dispatch-id` from the preamble, and `--outcome succeeded` only if every required check passed. Otherwise `--outcome failed`, and start the body with one reason code: `BLOCKED_CONTEXT`, `BLOCKED_PERMISSION`, `CHECKS_FAILED`, `CHECKS_UNAVAILABLE`, `OUT_OF_BUDGET`, `CANCELLED`, `OTHER`.

1. Changed paths, exactly as `git status --porcelain` shows them (the coordinator recomputes this from Git, so be accurate).

3. Any question you asked, the answer you received, and whether a timeout happened first.

Append `--files-modified` with the real paths. After `worker_done`, stop and idle. Do not poll, do not start new work, do not exit the shell.

Your result is evidence. It is not acceptance; the coordinator decides that after the ownership gate, review and integration.

+# mean: specification
+
+Status: approved 2026-10-14 (user instruction "commit and push then proceed", recorded as D-18 in the orchestration package). Open decisions OD-1 to OD-6 were settled by the user on 2026-10-14 (see Decisions). Revision and hash are pinned in every brief once approved; any edit creates new identities (K-5).

+Repository base observed: `main` at `9e3a1407eb88ed4a1494b84eca432fe03b2d087f` (read from `.git/refs/heads/main`; not yet confirmed with `git rev-parse`). Its file list was not inspected (no shell access); `src/math.mjs`, `test/math.test.mjs` and `package.json` were re-read on 2026-10-14 and still match this specification's assumptions.
+
+## Goal
+
+Callers of `src/math.mjs` get a `mean(values)` function that returns the arithmetic mean of a non-empty array of numbers, so averaging no longer has to be hand-written at each call site. The change is additive: the existing `add` and `clamp` functions and their tests keep their current behaviour.
+
+## Behaviour
+
+1. B-1: `src/math.mjs` exports a named function `mean` taking one parameter, `values`.
+2. B-2: For a non-empty array of finite numbers, `mean(values)` returns the sum of the elements divided by the number of elements.
+3. B-3: For a single-element array, `mean([x])` returns `x`.
+4. B-4: For an empty array, `mean([])` throws a `RangeError` (OD-1).
+5. B-5: For input that is not a plain array (`Array.isArray` is false, which includes typed arrays and array-likes), or an array containing an element that is not a finite number (including `NaN`, `Infinity`, strings, `null`, `undefined`), `mean` throws a `TypeError` (OD-2, OD-5).
+6. B-6: `mean` does not mutate its input array.
+7. B-7: Summation is plain left-to-right floating-point addition, then one division by the length; results are subject to normal IEEE 754 rounding (OD-3).
+
+## Non-goals
+
+- No support for iterables, array-likes or typed arrays; they are rejected per B-5 (OD-5).
+- No weighted, geometric, harmonic or trimmed means; no median or mode.
+- No compensated (Kahan or Neumaier) summation and no protection against intermediate overflow to `Infinity` for very large values (OD-3).
+- No fix to the existing `clamp` upper-bound defect (see Constraints and OD-4).
+- No changes to `package.json`, `.githooks/`, `AGENTS.md` or `scripts/`.
+
+## Constraints
+
+- No new dependencies: `package.json` unchanged, no lockfile created, no `node_modules/` required. Tests use only `node:test` and `node:assert/strict`, as today.
+- `add` and `clamp` in `src/math.mjs` stay byte-identical; changes to that file are additions only.
+- Existing test cases in `test/math.test.mjs` stay byte-identical. The only permitted edit to existing lines is extending the import on line 3 to include `mean`.
+- Changed paths are limited to `src/math.mjs` and `test/math.test.mjs` (AGENTS.md: do not edit files outside the task's paths). The only other path allowed in a candidate is `src/generated.mjs`, written and re-staged by the repository's pre-commit hook (`.githooks/pre-commit` runs `scripts/format.mjs`); it is declared as an expected hook-generated path in the task brief, is never edited by the implementer, and lands on `main` with the candidate (OD-6).
+- ES module syntax, consistent with `"type": "module"` and the existing file style (two-space indent, single quotes, semicolons).
+- Known baseline limitation (OD-4): `clamp` contains a deliberate defect (upper bound not applied), so the existing test `clamp respects upper bound` is expected to fail on the base commit and after this feature. It is reported as an accepted limitation and never counted as a passing check. This was established by reading the code; `npm test` has not yet been run on the base.

+## Goal
+
+Callers of `src/math.mjs` get a `mean(values)` function that returns the arithmetic mean of a non-empty array of numbers, so averaging no longer has to be hand-written at each call site. The change is additive: the existing `add` and `clamp` functions and their tests keep their current behaviour.
+
+## Behaviour
+
+1. B-1: `src/math.mjs` exports a named function `mean` taking one parameter, `values`.
+2. B-2: For a non-empty array of finite numbers, `mean(values)` returns the sum of the elements divided by the number of elements.
+3. B-3: For a single-element array, `mean([x])` returns `x`.
+4. B-4: For an empty array, `mean([])` throws a `RangeError` (OD-1).
+5. B-5: For input that is not a plain array (`Array.isArray` is false, which includes typed arrays and array-likes), or an array containing an element that is not a finite number (including `NaN`, `Infinity`, strings, `null`, `undefined`), `mean` throws a `TypeError` (OD-2, OD-5).
+6. B-6: `mean` does not mutate its input array.
+7. B-7: Summation is plain left-to-right floating-point addition, then one division by the length; results are subject to normal IEEE 754 rounding (OD-3).
+
+## Non-goals
+
+- No support for iterables, array-likes or typed arrays; they are rejected per B-5 (OD-5).
+- No weighted, geometric, harmonic or trimmed means; no median or mode.
+- No compensated (Kahan or Neumaier) summation and no protection against intermediate overflow to `Infinity` for very large values (OD-3).
+- No fix to the existing `clamp` upper-bound defect (see Constraints and OD-4).
+- No changes to `package.json`, `.githooks/`, `AGENTS.md` or `scripts/`.
